# Poler V2 识别修复与回归报告（2026-09-18）

本次修复只针对 `app=polerv2`。在目标机器的隔离代码副本执行识别；原始在线进程在候选验证阶段保持运行。发布状态以后续部署记录为准，本报告本身不代表已经上线。

## 修复内容

- 手牌角标裁剪去除花色和人物画干扰，保留两位数 10；宽而短的旧截图裁剪继续走原来的兼容路径。修正面牌花色角标区域，避免红桃/方块等混淆。
- 公共牌增加白色牌面检查，避免半透明遮罩下将桌面文字识别成五张牌；面牌花色使用独立角标。
- 庄位取消从手牌附近黑色块直接猜 seat=1 的捷径，要求白色候选接近圆形，排除操作文字。
- hero 筹码锚点和局部 OCR 对齐实际余额区域；从独立下注位置读取已投入金额，避免把跟注按钮的待付金额读成下注。
- 灰色预操作按钮不再触发 hero 行动；确认买入倒计时归类 waiting，不作为筹码。空座视觉预检仅用于 active 且没有 OCR 余额的座位，保留已确认弃牌/余额，避免颜色规则覆盖明确文本。
- 左上座位的红色下注牌允许较小完整牌面，修复 1/2/4 漏读。空牌背先排除小字/logo；下注数字轮廓明确时调用 RapidOCR 单行识别，低置信度/其他后端保留原 OCR 路径。

## 性能口径

同一目标机器，4 vCPU、约 3.6 GiB 内存，Python 3.12.3，RapidOCR ONNX Runtime 1.4.4、ONNX Runtime 1.26.0、NumPy 2.4.4、OpenCV 4.13.0.92。单进程串行执行，不与其他 OCR 回归并发；初始化单独记录。

耗时为 `recognize(parse_all=True)` 核心调用，包含图片解码及预处理，不包含 HTTP 上传、网络、排队。P95 为 nearest-rank。旧版基准均值 2.014 秒、P95 2.737 秒；更正人工标签不改变原始耗时记录。主要耗时仍为全图 OCR 与少数局部补读，修复不代表消除全部延迟或证明高并发容量。
